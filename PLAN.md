# ShieldTX concept v2

Build on Eeshita's architectural identity and the team's conceptual feedback. Preserve the original static architecture and bundled fonts/libraries.

## Experience

1. **Hero:** cobalt architectural scene with a full three-quarter institution and a geometric trade object. Lead with a recognisable trading benefit. Start trading is primary; API access is secondary. Make beta access visible.
2. **Exposure:** illustrate the distinction between a public position and its funding-wallet association. Interactive before/after comparison uses a clearly labelled example. Place a compact scanner invitation here and a link in navigation.
3. **Walkthrough:** four visible stages—fund, shield, create, execute—with one short optional animation, manual step selection, pause and replay. Never capture or lock scrolling. Explain proceeds returning and that onchain activity stays public.
4. **Product:** use a real, suitable asset from the official product demonstration. Distinguish terminal and API routes. Include concise, source-grounded disclosures about custody/control and execution tradeoffs.
5. **Close:** clear trading and integration actions, FAQ, scanner, trust-model and support links.

## Visual system

- Cobalt hero; warm neutral explanatory sections; navy product and footer.
- Preserve serif display and DM Sans. Existing ShieldTX logo remains unchanged.
- Architectural geometry and consistent line weights replace mixed icon treatments.
- Restrained mint identifies the Hyperliquid destination/active state, rather than an unexplained glowing orb.
- The same example position identifier appears throughout the journey.

## Scope and safeguards

- No trading, wallet connection, or new data collection on the concept site.
- Functional links use official ShieldTX destinations; scanner validates a public address then hands off to the official scanner.
- No invented exposure results, testimonials, audit badges, pricing, supported funding, or privacy guarantees.
- Keep the original repository intact; implement on this fork's concept-v2 branch.
- Preserve static delivery. Add a minimal build adapter only for private Sites hosting.

## Verification and delivery

- Check HTML structure, linked local assets, JavaScript syntax, and the walkthrough state machine (pause/manual/replay/reduced motion/visibility).
- Review responsive rules for small/mobile, tablet and desktop layouts; ensure keyboard labels and focus states.
- Build and package the exact committed source, push to the fork, and publish an owner-private Sites review URL.
- Deliver plan, fork and review link with any material limitations.
